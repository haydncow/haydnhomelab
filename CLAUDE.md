# Notes for Claude

This is Haydn Cowley's homelab repo. It powers haydnhomelab.com. Read this first.

## Keep this file up to date
Whenever something changes in the homelab or the website (a new service, a new page, a new setting on the Pi, a fix), update this file and add a line to `docs/build-log.md` in the same commit. That way the next chat knows about it.

## The setup
- Raspberry Pi 5 (2GB), Debian 13, umask 027: new files need `chmod 644`, new folders `chmod 755`.
- Switch port 1 to router (via a TP-Link wireless box to the EE hub), port 2 to the Pi, port 3 to the PC. 1TB My Passport on the Pi's USB (runs at USB 2 speed).
- Services: Pi-hole (admin 8090) + Unbound (127.0.0.1:5335), Tailscale, UFW, Fail2ban, SSH keys only, OpenCanary honeypot (2222, 3389, 8081), Jellyfin, Homepage and Speedtest Tracker in Docker, Samba, nightly age-encrypted backups, ntfy phone alerts, CrowdSec (local API moved to 127.0.0.1:8085 because Caddy has 8080), weekly Trivy scan of Docker images (`/usr/local/bin/homelab-trivy`, cron Mondays, results in `/var/lib/homelab-trivy/last.json`).
- Website: Caddy (`/etc/caddy/Caddyfile`) serves `/srv/status` through a Cloudflare Tunnel. No open router ports. Strict CSP, no inline scripts. Every page, the live lab included, follows the light/dark setting, and phones always get dark.

## Where things are
| Repo | On the Pi |
|---|---|
| `setup/website/index.html` portfolio | `/srv/status/index.html` |
| `setup/website/lab/` live lab (index.html, app.js) | `/srv/status/lab/` |
| `setup/website/status/`, `writeups/`, `assets/`, `fonts/` | same under `/srv/status/` |
| `setup/website/homelab-status.py` stats, alerts, history | `/usr/local/bin/homelab-status.py` (root cron, every minute; always deploy to this exact name) |
| `setup/backup/homelab-backup.sh` | nightly backup |
| `setup/caddy/Caddyfile` | `/etc/caddy/Caddyfile` |

Secrets live only on the Pi in root-only `/etc/homelab-status/` (Pi-hole password, Cloudflare token, ntfy topic, maintenance.json). State in `/var/lib/homelab-status/`.

Only the homepage is indexed by Google; every other page has `noindex` on purpose.

The portfolio (`setup/website/index.html` + `portfolio.js`, version 5 from 30 Oct 2026) is written for employers. Haydn turned down an earlier "AI looking" version, so keep it free of template chrome (pill chips, coloured headline words, uppercase or mono labels, card grids, gradients, fade-ins). The look: grey paper, black type, one typeface (Archivo, self-hosted in `fonts/`, mono only for real command output), colour only for status (green passed or online, red attack, amber partly). The hero is his name, a live sentence built from the Cloudflare firewall feed in `history.json` (paths only ever added as text), and the rack cut out of its photo standing on a "desk line". Section headings hang in the left column. Near the end there is a Write-ups section listing every write-up (add new ones there too, as well as `writeups/index.html`). Photos and evidence screenshots are in `assets/` (`rack-angle-*`, `rack-front-*`, `headers-before/after`, `waf-events`); the cutouts were made with rembg. It prints as a 3-page summary. Facts on it must match `docs/build-log.md`.

The live lab (`lab/index.html` + `lab/app.js`, version 5 from 30 Oct 2026) has the same look and replaced the always-dark "control room" version. Headline numbers along the top, then ruled panels instead of cards: the rack, security, what's running, the welcome or part details, Pi-hole and the Pi (a spec-sheet list with a small line per reading). The rack is the real front photo (`assets/rack-front-1056.webp`): each part is clickable and zooms in, and the light dots sit on its real LEDs and only blink while the Pi is online. They're the only thing that moves by itself (no ticker, count-ups or boot screen). Panels size to their content and fill the screen on a laptop; tablets get the rack first, phones the numbers first. The details views (network map, attack map, 30-day history, how it works) open over the page.

Write-ups, the status page and the live lab share `assets/site.css` and the same top bar (`Haydn<span class="last"> Cowley</span>`, nav on the right). The write-up and status HTML is generated by a script kept outside the repo, so edit the HTML directly and keep the top bar the same on every page.
